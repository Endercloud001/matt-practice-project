# `clean-list.md` 输出模板

将尖括号中的占位内容替换为实际信息。内容应保持“先保留、后候选”的顺序；表格中的路径可以是相对项目根目录的路径，但跨根目录的内容必须同时给出绝对路径或缩写展开。

```markdown
# <范围> 清理清单

盘点日期：<YYYY-MM-DD>。本文件只记录清理建议，尚未执行删除。

## 判定依据与路径

- 当前项目根目录：`<absolute-project-root>`。
- 当前分支和提交：`<branch>` / `<commit>`。
- 远端跟踪引用：`<remote-ref and observed state>`。
- `W` 代表 `<absolute-worktree-root>`；所有 `W/` 路径执行前必须展开。
- 旧 issue、组件、脚本和工作区按当前本地状态及可确认的最新远端引用比较；不确定处列在“需要用户审查”。
- 通配符只作用于本节明确的目录；未跟踪或被忽略不等于无用。

## 1. 明确保留

| 路径     | 保留原因                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------- |
| `<path>` | `<源码、配置、当前修改、最终验收结论、尚未被替代的故障注入脚本/过程截图、唯一证据或其他具体原因>` |

## 2. 可重新生成的产物

| 路径     | 建议、前置条件和依据                       |
| -------- | ------------------------------------------ |
| `<path>` | `<停止依赖服务后可重新生成；说明生成来源>` |

## 3. 临时日志、截图和验收资料

| 文件或限定模式              | 建议、前置条件和依据                       |
| --------------------------- | ------------------------------------------ |
| `<bounded-path-or-pattern>` | `<过程文件；说明对应的最终证据是否已保留>` |

## 4. 旧文档、计划与交接

| 路径     | 建议、前置条件和依据                       |
| -------- | ------------------------------------------ |
| `<path>` | `<确认独有决定已迁移、链接已处理后再清理>` |

## 5. 旧实现与一次性脚本

| 路径     | 建议、前置条件和依据                   |
| -------- | -------------------------------------- |
| `<path>` | `<当前基线已覆盖或仍需审查的具体证据>` |

## 6. 工作区、分支与 stash

| 对象                | 当前证据                           | 建议和前置条件                                   |
| ------------------- | ---------------------------------- | ------------------------------------------------ |
| `<worktree-or-ref>` | `<status, ancestry, unique files>` | `<迁出保留项后再处理；不要直接删除 .git 元数据>` |

## 7. 需要用户审查

| 路径或对象 | 未决问题                       | 建议的核对方式                          |
| ---------- | ------------------------------ | --------------------------------------- |
| `<path>`   | `<无法证明是否仍需保留的原因>` | `<指定文档、issue、远端记录或人工决定>` |

## 8. 执行顺序与完成检查

1. 重新检查 Git 状态、未提交内容、合并状态、worktree 列表、远端引用和清单中的保留项。
2. 停止并确认依赖候选文件的服务、浏览器或采集进程。
3. 先迁出独有验收证据、配置、数据库和文档，再处理候选产物。
4. 逐项解析绝对路径并确认位于清单指定根目录内；不执行未列出的广泛删除。
5. 清理后检查 `git status`、保留文档链接、业务源码、测试、迁移和运行配置；只有跟踪文件或运行行为变化时才运行相应验证。
```
